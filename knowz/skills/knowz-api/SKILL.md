# Knowz API

Use the direct REST API as a guarded power-user layer. Prefer Knowz MCP for routine knowledge work
and the `knowz` CLI for supported command-line workflows. Use this skill when the requested client
operation needs live API discovery or capabilities those layers do not expose.

## Run guided setup first

Set `SKILL_DIR` to this skill directory, then use:

```bash
python3 "$SKILL_DIR/scripts/knowz_api.py" setup --json-output
```

Read `ready`, `authenticationCheck`, and `nextSteps`. Never ask the user to paste a key into chat or
put it in a command argument. If setup reports `ready: false`, guide the user through the reported
steps and rerun it. Use `--no-verify` only for offline inspection; normal setup verifies the key with
the non-mutating validation endpoint without printing the key or identity response.

The standard-library client resolves credentials automatically in this order:

1. `KNOWZ_API_KEY` (or `--key-env NAME`) in the current agent process.
2. The environment variable named by Codex MCP config, or a private API key already present in a
   known project/user MCP config for Gemini, Claude, VS Code, Cursor, or compatible clients.
3. On macOS, the active authenticated `knowz` CLI profile when its key is in the OS keychain. The OS
   may ask the user to approve access; the key remains in memory and is never printed.

MCP OAuth sessions are not converted into API keys. CLI encrypted-file credentials are not decrypted
by this skill. In those cases setup explains the safe fallback. A future `knowz api` credential broker
can replace platform-specific keychain sharing without changing this skill's user workflow.

The remaining configuration resolves in this order:

- OpenAPI: `--spec`, `KNOWZ_OPENAPI_SPEC`, a nearby `knowz-platform` checkout, then the resolved
  API server's `/swagger/v1/swagger.json`.
- API base URL: `--base-url`, `KNOWZ_API_URL`, `enterprise.json#/api_endpoint`, the active non-secret
  Knowz CLI profile, then `https://api.knowz.io`.

For enterprise or self-hosted use, prefer `enterprise.json` or set both environment variables.
Allow plain HTTP only for loopback hosts.

After setup is ready, inspect the contract source:

```bash
python3 "$SKILL_DIR/scripts/knowz_api.py" source
```

## Choose the access layer

1. Use MCP for ask/search/save/amend/browse and vault-aware knowledge work.
2. Use the `knowz` CLI when it already has a supported command, especially local-first workflows.
3. Use this direct API skill for live schema discovery, advanced uploads, processing controls, or
   other safe client endpoints absent from those layers.
4. If the client blocks an operation, do not bypass it with `curl`, generated code, or a different
   HTTP library. Explain the boundary and direct the user to the web app, CLI, or a human operator.

## Discover before calling

Search only the permitted client surface:

```bash
python3 "$SKILL_DIR/scripts/knowz_api.py" discover --query "enrichment status"
python3 "$SKILL_DIR/scripts/knowz_api.py" describe GetEnrichmentQuality
python3 "$SKILL_DIR/scripts/knowz_api.py" describe 'POST /api/v1/knowledge/{id}/enrich/agentic'
```

Run `describe` before every unfamiliar operation. Verify its method, path, parameters, content
type, request schema, and impact. The tool resolves component schemas recursively so detailed API
shapes stay current without loading the whole Swagger document into context.

Read [references/common-operations.md](references/common-operations.md) for invocation patterns,
response envelopes, uploads, reprocessing, and troubleshooting. Read
[references/safety-policy.md](references/safety-policy.md) before any mutation or whenever an
operation is blocked.

## Execute a permitted operation

Use `request` for operations discovered from the live spec:

```bash
python3 "$SKILL_DIR/scripts/knowz_api.py" request GetUploadProgress \
  --path uploadId="$UPLOAD_ID"

python3 "$SKILL_DIR/scripts/knowz_api.py" request UpdateKnowledgeAiSummary \
  --path id="$KNOWLEDGE_ID" \
  --json-file /absolute/path/to/payload.json \
  --execute
```

Rules:

- Treat a clear user request for the exact mutation and exact target as authorization. Otherwise,
  preview the operation and ask before using `--execute`.
- Require `--execute` for POST, PUT, PATCH, and other state-changing methods. GET/HEAD remain
  read-only.
- Resolve and validate every target ID before a mutation. Do not guess IDs from titles.
- Prefer `--json-file` over inline JSON for non-trivial payloads. Never place secrets in payloads.
- Add `--idempotency-key` when retrying a create-like mutation that supports idempotency, and reuse
  the same stable key for the same logical operation.
- Report the operation ID, method/path, target, status, and useful result. Do not print credentials.

## Use guarded workflows

Prefer the built-in workflows over manually composing their low-level calls:

```bash
python3 "$SKILL_DIR/scripts/knowz_api.py" upload /absolute/path/to/file.pdf \
  --create-as knowledge --vault-id "$VAULT_ID" --title "Source document" --execute

python3 "$SKILL_DIR/scripts/knowz_api.py" reprocess "$FILE_RECORD_ID" --execute

python3 "$SKILL_DIR/scripts/knowz_api.py" reindex "$KNOWLEDGE_ID" --execute
```

The upload workflow follows the server-advertised chunk size, hashes chunks, completes the upload,
and can create a standalone file, inbox item, or knowledge item. It never cancels or deletes an
upload session after failure; server expiry handles abandoned sessions.

## Maintain the boundary

- Expose only tenant-scoped client operations that pass the bundled policy.
- Never expose or invoke DELETE operations, administration, super-administration, authentication,
  SSO, billing, tenant control-plane, key/secret management, diagnostics purge, cache control,
  bulk import/export/sync, public upload, internal callback, test-only, or global/bulk rebuild
  operations.
- Do not invoke streaming/SSE endpoints through this client.
- Do not weaken the policy or add an override at runtime. A missing advanced operation is a skill
  maintenance request, not a reason to bypass the boundary.
- Treat OpenAPI as the contract for shape, not proof of authorization. Server-side tenant and vault
  access checks remain authoritative.
